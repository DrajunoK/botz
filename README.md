# Botz

A physics-based, simultaneous-turn team sports game for mobile (Android + iOS), where the players are small round robots. V1 ships a single mini-game: **soccer**, 3 botz per team. Full spec: [`specs/BOTZ_SPEC.md`](specs/BOTZ_SPEC.md); design mockups: `specs/`.

What makes it different from a plain "launch the blobs" game — two twists:

1. **Botz fall apart.** Every hard hit (bot–bot or bot–wall) knocks one of their 4 parts off — antenna (blurry aim ±10°), left / right arm (the trajectory drifts right / left), wheel (spins and brakes irregularly). Each lost part also makes the bot lighter. A bot with nothing left is a smoking wreck. Lost parts become physical debris on the pitch and stay lost for the whole match.
2. **The ball is an alarm clock that runs away.** It rings, flees the botz on its own during each resolution (sliding along walls, never staying stuck in a corner), and panics more and more as turns go by: *Somnolent* (turns 1–3) → *Réveillé* (4–6) → *Inquiet* (7–10) → *Panique* (11+). A goal calms it down by one notch. A hard hit stuns it for 1.5 s.

Built with TypeScript, Vite, [Phaser 3](https://phaser.io/) (rendering + game loop) and Phaser's built-in Matter.js integration (physics), stepped manually at a fixed 60 Hz. Packaged for mobile with [Capacitor](https://capacitorjs.com/).

## Requirements

- Node.js 18+
- For Android builds: Android Studio (SDK + an emulator or device)
- For iOS builds: a Mac with Xcode + an Apple Developer account (to deploy to a device / publish)

## Development

```bash
npm install
npm run dev       # starts Vite on http://localhost:5173
```

Open the URL in a browser, landscape orientation recommended (the game runs at a logical 1600x900 resolution, scaled with `Phaser.Scale.FIT`).

## Testing

Gameplay logic (turn state machine, aiming math, AI, part loss, panic, alarm steering, RNG) is framework-agnostic and unit-tested with Vitest:

```bash
npm run test        # run once
npm run test:watch  # watch mode
```

## Building for the web

```bash
npm run build      # type-checks then builds to dist/
npm run preview    # serve the production build locally
```

## Tuning

Every gameplay knob lives in `src/config/`:

| File | What |
|---|---|
| `physics.ts` | radii, restitution, friction, shot speed, fixed timestep |
| `parts.ts` | part-loss impact threshold, cooldown, mass loss, drift / aim-error / wheel effects, debris cap, `REPAIR_ON_GOAL` |
| `alarmClock.ts` | panic levels (turn thresholds, flee force, ring cadence), run time, stun, wall following |
| `game.ts` | goals to win, aim timer, settle thresholds |
| `theme.ts` | palette and fonts from the mockups |

All randomness (lost part choice, aim error, flee direction, AI noise) goes through the seeded `Rng` (`src/game/Rng.ts`), never `Math.random()`. A match is described by its seed (`MatchConfig.seed`).

## Project structure

```
src/
  main.ts             Phaser game bootstrap
  styles.css          @font-face for Bungee + Fredoka (src/assets/fonts, SIL OFL)
  config/             physics, parts, alarmClock, game, theme
  scenes/             BootScene (waits for fonts), MenuScene, GameScene, ResultScene
  game/
    Rng.ts            seeded random generator (mulberry32)
    TurnManager.ts    AIMING -> RESOLVING -> (GOAL_PAUSE) -> ... state machine
    DamageSystem.ts   hard-hit detection, part loss, per-bot cooldown
    Panic.ts          panic level from the turn number, calm-down on goal
    alarmSteering.ts  flee direction (away from bots, wall following, un-sticking)
    AimController.ts  touch input: drag-to-aim, tap-to-clear
    AIController.ts   rule-based AI (attacker / defender / support), difficulty noise
    entities/         Bot, BotParts (pure part logic), AlarmClock, Debris
    field/            SoccerField, fieldGeometry (wall distance queries)
    modes/            GameMode (interface), SoccerMode
    view/             BotView, AlarmClockView and their Graphics art (swap for sprites later)
    Audio.ts          synthesized SFX (Web Audio): clonks, alarm ring, stun, goal
  ui/                 Button, HUD, Overlays (pause, pass & play hand-off, goal flash, sparks)
  state/              settings.ts (sound, difficulty — persisted to localStorage)
```

## Icon & splash screen

`resources/icon.png` and `resources/splash.png` are generated procedurally by `scripts/generate-assets.mjs` (a small from-scratch PNG encoder in `scripts/png.mjs` — no external image tools or network access needed), drawing the botz and the alarm clock in the same style as the mockups. Regenerate them, then re-run the platform asset generator, whenever the design changes:

```bash
node scripts/generate-assets.mjs
npx capacitor-assets generate   # writes Android mipmaps/splash and iOS AppIcon/Splash assets
npm run cap:sync
```

## Mobile builds (Capacitor)

The `android/` and `ios/` folders are native Capacitor projects generated by `npx cap add <platform>`. They're checked in like any other native project. Whenever web code changes, rebuild and sync before opening/building the native project:

```bash
npm run cap:sync     # npm run build + npx cap sync (both platforms)
```

### Android

Requires [Android Studio](https://developer.android.com/studio) (which bundles the Android SDK).

```bash
npm run cap:android  # builds web, syncs, opens android/ in Android Studio
```

From Android Studio: let Gradle sync finish, pick a device/emulator, hit Run. To produce a release APK/AAB, use Android Studio's *Build > Generate Signed App Bundle / APK*, or `cd android && ./gradlew assembleDebug` for an unsigned debug APK (output under `android/app/build/outputs/apk/`).

### iOS

Requires a Mac with Xcode and CocoaPods (`sudo gem install cocoapods`, or via Homebrew), and an Apple Developer account to run on a physical device or publish.

```bash
npm run cap:ios      # builds web, syncs, opens ios/App/App.xcworkspace in Xcode
```

The first `cap sync` on a machine with CocoaPods installed will run `pod install` automatically. From Xcode: pick a signing team under *Signing & Capabilities*, choose a simulator or device, hit Run.

### Notes

- `capacitor.config.ts` sets the app id (`com.botz.game`) and name (`Botz`) used by both platforms.
- These native projects were scaffolded in a Linux sandbox without the Android SDK or Xcode installed, so `./gradlew` and `pod install` have not actually been exercised here — verify a full build on a machine with the real toolchains before shipping.
